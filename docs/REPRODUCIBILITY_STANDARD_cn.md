# 科研项目整理与可复现交付规范

## 一、唯一的交付标准

**项目不能仅仅以“程序在开发者电脑上运行成功”作为完成标准，而要以“从干净的项目副本可以依照文档重建结果”作为交付标准。**

本规范适用于使用 AI 工具整理已有科研项目。任务不是把文件复制、改名、分文件夹就结束，而是在**不改变原始数据、科学方法和研究结论**的前提下，消除隐藏依赖，建立清楚的数据流和运行入口，并通过独立副本验证。

“干净的项目副本”指一个新目录：不能依靠原项目目录、作者电脑上的其他文件、未经说明的安装环境、外部软链接或本地绝对路径运行。确实需要网络、商业软件、GPU、集群或无法随项目分发的数据时，必须明确列出依赖和获取步骤，并说明哪些结果已实际复现。

## 二、必须遵守的原则

1. **原始数据集中且不可覆盖。** 所有未处理的源数据放入 `raw_data/`。不得以清洗、统一格式、改列名等理由覆盖原始文件。原件保留内容和校验值；若仅规范化文件名，必须保存新旧名称映射。
2. **处理数据集中管理。** 清洗、筛选、转换、合并、归一化等产生的文件放入 `processed_data/`，注明生成它们的程序、输入和参数。中间结果与正式结果应可区分。
3. **全部绘图输入集中且可理解。** 每幅图、每个子图所需的数据放入 `figure_data/`，优先采用明确列名的 CSV 等通用格式；说明各列含义、单位、误差条、拟合曲线和归一化方式。画图程序应能直接从这些文件重建图，而不必重复昂贵的上游计算。
4. **禁止本地绝对路径和隐藏依赖。** Python、shell、配置、notebook、批处理程序及其调用链不得写入开发者的本地绝对路径。使用项目根目录定位和相对路径；不得通过指向原文件夹的软链接伪装为项目内部文件。
5. **严格执行语言隔离。** 程序、配置、数据文件、文件名和英文文档均不得含中文字符。中文仅允许出现在 Markdown 中；中文 Markdown 文件名必须醒目标注 `cn`，例如 `README_cn.md`，而且必须有独立的纯英文对应文档 `README.md`。英文文档即使是解释中文术语，也不得含任何中文字符；必要的中英对应另写 `TERMINOLOGY_cn.md`，并配备纯英文 `TERMINOLOGY.md`。
6. **程序在项目根目录可运行。** 从交付目录执行文档中的命令即可运行。入口脚本、相互调用的脚本及输出目录均要适配新结构；不应要求手工修改代码或切换到作者机器上的特殊路径。
7. **建立数据溯源。** 每个重要文件必须能追踪“原始输入 → 处理脚本和参数 → 中间产物 → 绘图数据或统计结果”。提供英文 `data_manifest.csv`，不能出现无法解释来源的数据。
8. **统一结果对应关系。** 每个正式图表与重要统计结论都要能定位对应程序、输入、运行命令和输出文件。提供 `figure_manifest.csv`；不要只保留图片而丢掉生成过程。
9. **记录环境与外部程序。** 记录 Python、依赖库、系统命令、模型权重及外部软件版本。提供 `requirements.txt` 或 `environment.yml`，以及额外安装说明。重要结果不能依赖“本机恰好装过”的包。
10. **控制随机性与样本划分。** 保存随机种子、数据筛选规则、训练/验证/测试划分、bootstrap 采样方案和重要运行参数。具有不可避免的硬件非确定性时说明可接受的数值差异。
11. **有明确的执行顺序。** 提供项目级入口（如 `run_all.py`），或者一份可直接复制执行的顺序命令。支持至少两种路径：从 `figure_data/` 快速重画全部图；从 `raw_data/` 完整重建结果（昂贵步骤可单独执行）。
12. **保持科学计算等价。** 路径、文件读写、导入方式和运行环境可以修复；涉及算法、阈值、样本选取、归一化、单位、模型参数、统计口径和绘图含义的改变，必须单独说明并由负责人确认，不能混在文件清理中悄悄修改。
13. **命名稳定，禁止误覆盖。** 新生成的文件使用英文、数字、下划线及必要的版本/参数/seed 标识，避免 `final_new2` 等命名。不得静默覆盖重要原始数据和既有结果；缓存、临时文件、正式输出分开。
14. **清理有记录，不擅自删文件。** 删除重复、过时或无用文件前，先根据校验值及依赖关系确认。保留新旧路径映射、删除/保留依据和变更日志。原始项目始终保持不变。
15. **保护保密信息。** 检查密钥、令牌、账号、个人目录、未授权共享的数据、机密结果及许可证限制。不得把敏感数据擅自上传给第三方 AI 服务；凭据应以环境变量或受控配置注入，不随项目交付。
16. **以独立验证作为验收。** 静态检查、运行测试、数值对照、论文图复现和干净副本验证全部留下日志。失败项必须如实标注；“没有报错”不等于结果正确。

**规则冲突的处理：** 如果原始文件内已有中文，原件不可修改与交付包数据不得含中文会直接冲突。AI 不得擅自翻译或清洗原件来宣称两项均已满足；应将其列为阻断项，由负责人决定是否在交付包外保留原件、建立有审计记录的规范化工作副本，或批准明确的例外。若原件不随包交付，还须检查是否破坏“独立副本重建”的标准。Excel 的单元格、工作表名、批注、公式和隐藏工作表也在检查范围内。

## 三、建议的交付目录

```text
project/
├── README.md
├── README_cn.md
├── requirements.txt             # or environment.yml
├── data_manifest.csv
├── figure_manifest.csv
├── file_migration_map.csv
├── CHANGELOG.md
├── config/
├── raw_data/
├── processed_data/
├── figure_data/
│   ├── fig01/
│   └── fig02/
├── scripts/
│   ├── preprocessing/
│   ├── analysis/
│   └── plotting/
├── results/
│   ├── figures/
│   ├── tables/
│   └── logs/
├── tests/
├── run_all.py
└── validate_project.py
```

这是参考结构。可根据项目规模合并小目录，但 `raw_data/`、`processed_data/`、`figure_data/`、正式结果与程序应有清楚边界。正式提交前不要把原项目备份、测试副本、无关缓存一起打包。

## 四、学生和 AI 的完整执行流程

### 阶段 0：冻结原项目，确定基准

- 将项目分别保留为 **只读原项目**、**整理工作副本** 和稍后创建的 **独立验收副本**。不得在原目录直接进行批量移动、删除或重写。
- 记录原有目录树、核心文件的 SHA-256 校验值、现有运行命令、Python/外部程序版本、可获取的已有图表和统计数值。
- 尽可能在原环境跑一次现有流程，记录成功和失败的环节。若原项目本来无法完整运行，必须写明“原始基准缺失”，不能后续声称严格等价已得到证明。

**阶段产出：** `inventory.csv`（初始）、`baseline_report.md`、重要输入/输出的校验值。

### 阶段 1：先盘点和画依赖图，不急着移动

- 递归登记所有文件：相对路径、类型、大小、校验值、编码、角色、是否重复、是否临时文件、是否含中文，以及是否出现本地路径。
- 对程序做静态与必要的动态检查，查清其读取哪些文件、写出哪些文件、如何传递参数、调用哪些脚本、程序或网络资源。特别检查 `os.chdir`、工作目录假设、软链接、notebook、环境变量、绝对路径和硬编码文件名。
- 对 Excel 检查工作表与列名、公式、隐藏表等；对二进制数据和模型权重记录格式与加载方式。无法可靠自动解析的内容应列为“待人工核验”，不能视为已经通过。
- 把文件标记为：原始输入、处理数据、绘图数据、代码、配置、正式结果、文档、缓存/临时文件、未知。未知文件不得直接删除。

**阶段产出：** 完整文件清单、程序依赖关系、问题清单、建议迁移表。**此时先审阅迁移方案，再允许 AI 修改。**

### 阶段 2：建立新目录和迁移映射

- 在工作副本中创建目标结构，按确认后的归类搬迁文件。
- 生成 `file_migration_map.csv`，逐项记录旧路径、新路径、动作（保留/移动/改名/再生成/候选删除）、原因及校验值。
- 内容相同的重复文件可先归并引用，但必须确认程序不依赖某个旧路径；内容相似但不完全一致的文件不得仅凭文件名判断为重复。
- 所有源文件优先按字节复制或移动，不通过表格软件重新保存原始 Excel，也不自动改变数值精度、空值和单位。

**阶段产出：** 新目录骨架、迁移映射、未处理的冲突清单。

### 阶段 3：修复程序，让新目录真正独立

- 统一相对路径解析，优先从程序文件位置推断项目根目录，或通过统一配置/命令行参数传递；输入和输出均不能指回原目录。
- 修复文件迁移导致的导入、调用顺序、shell 命令、大小写、路径分隔符、输出目录创建和权限问题。
- 将版本、重要参数、随机种子和输出约定集中管理；保留默认配置，减少人工编辑程序的必要。
- 不在同一步中“顺便优化算法”。任何可能影响数值的改动，都单独记录差异、验证依据和审批结果。

**阶段产出：** 新目录内可执行的程序、统一配置、变更日志。

### 阶段 4：打通数据和绘图两条链

- **完整链：** `raw_data/ → processed_data/ → figure_data/ → results/`。确认每一步的输入、输出、参数、生成程序和顺序。
- **快速绘图链：** `figure_data/ → results/figures/`。每张图可依据 `figure_manifest.csv` 确定数据文件和绘图命令；带有误差条、拟合和统计标注的图，必须保存这些元素所需的数据或明确的可重复计算方式。
- 生成 `data_manifest.csv`（文件、来源、生成步骤、关键字段、单位、用途）、`figure_manifest.csv`（图号/子图、数据文件、画图脚本、命令、输出文件）。
- 绘图数据尽可能采用不依赖 Python pickle 或特定开发环境的格式。对于体积过大的中间数据，可以提供明确的再生成步骤，但绘图必需的数据应当随项目交付。

**阶段产出：** 完整处理流程、可独立运行的画图流程和两份清单。

### 阶段 5：整理文档、依赖和语言规范

- 编写纯英文 `README.md`，写明项目目的、目录结构、数据来源、软件安装、最短运行命令、完整运行步骤、计算资源需求、预期输出和已知限制。
- 如果需要中文说明，提供内容对应的 `README_cn.md`；其他中文 Markdown 也同样配备纯英文对应文件。
- 清理程序和数据中的中文字符，扫描文件名、文本、代码注释、CSV、Excel 单元格与表名及可以解析的元数据。不可解析的二进制格式单独核验。
- 补全依赖版本及外部命令说明，建立 `.gitignore`，排除缓存、虚拟环境、敏感配置和无关临时文件；不要因为忽略规则而漏掉必须交付的数据。

**阶段产出：** 双语分离文档、环境说明、语言和路径检查记录。

### 阶段 6：分层测试，而非只做一次运行

1. **静态合规测试：** 目录分类、文件缺失、中文字符、绝对路径、外部软链接、危险凭据、manifest 引用、脚本语法及依赖检查。
2. **轻量运行测试：** 在项目根目录执行小样本或短流程，验证读取、计算、写出及绘图都能成功。
3. **完整计算测试：** 按文档运行正式流程，核对重要输出的数据形状、样本数量、单位、统计量、拟合参数、随机种子和图表。确定性结果优先比较校验值或精确数值；浮点/GPU 结果应先规定容差再比较，不能事后任意放宽。
4. **独立副本测试：** 把整理完成的目录再复制到一个新的、不同位置的验收目录，隔离原项目路径，并在按文档配置的干净环境中重新运行。至少须完整通过快速绘图链；完整计算链若因计算资源限制未执行，必须明确写出未验证范围及理由。

**阶段产出：** 英文 `validation_report.md`（如需中文再配 `_cn.md`）、测试日志、数值差异表和未通过项。

### 阶段 7：交付前审查和封存

- 学生检查迁移表、所有被删除或排除的文件、科学计算改动、尚未通过的测试，以及图表和原结果的差异。
- AI 提供变更摘要，明确区分“已实际运行并验证”“仅通过静态检查”“未验证”“已知失败”，不能把计划中的运行写成已完成。
- 在批准之前保留原项目和整理过程的备份。确认最终版本后，再清理临时目录并为交付文件生成最终校验值清单。

**最终必须交付：** 可运行的项目文件夹、英文 README（如有中文说明需提供成对文件）、依赖环境、数据与绘图 manifest、新旧路径映射、变更记录、验证报告，以及一组可直接执行的复现命令。

## 五、最终验收判定

只有同时满足以下条件，才能标注 **PASS**：

- 原始项目没有被覆盖，原始数据可追溯；所有文件分类明确且不再依赖旧目录。
- 本地绝对路径、外部软链接、未经声明的资源和中文字符限制均通过检查。
- 仅依照 README，在新目录中完成环境安装、数据读取、程序运行、输出生成；无需修改代码内容。
- 全部正式图具有可理解的绘图数据与对应脚本，快速绘图链实际运行通过。
- 核心数值结果与整理前的基准一致，或差异在事先规定的合理容差内，并有对照证据。
- 如有完整计算链未运行、原始文件语言冲突、外部数据未归档或原始基准缺失，必须标为 **EXCEPTION / NOT VERIFIED**，而不是 PASS。

**最终评价依据不是目录看起来多整齐，而是能否把项目复制到一个干净的位置，让没有参与开发的人按照文档真正重建结果。**

## 六、可直接交给 AI 编程工具的任务指令

> 你是科研计算项目的整理与复现工程助手。请在指定的原项目目录之外创建一个新的交付目录，严格按照本规范工作。原项目只读，不得覆盖、修改或删除。第一步仅盘点文件、分析程序依赖、发现风险并提出迁移方案，输出完整清单和新旧路径映射草案；未经确认，不要执行有风险的批量重命名、删除、数据格式转换或算法修改。确认方案后分阶段迁移并修复全部路径、环境、运行入口、数据溯源与绘图输入。任何程序或数据文件不得含中文，中文说明只能位于标注 `cn` 且有纯英文对应文件的 Markdown 中。每次修改后执行相应测试，最终在与原项目无关的干净副本中依照 README 重新运行，比较关键数据和图表。输出文件清单、迁移映射、修改记录、依赖环境、两条复现路径和验证报告。对不能实际运行、无法判断用途、会影响科研数值或触及规范冲突的事项，明确报告并交由负责人判断。绝不把未经执行的检查写成通过。
